Terraform Basics

A beginner-friendly guide to Infrastructure as Code using Terraform

What is Terraform?

Terraform is an Infrastructure as Code tool used to create and manage infrastructure using configuration files.

Instead of manually creating resources in AWS, Azure, or GCP, you write code and Terraform creates them for you. 

resource "aws_instance" "web_server" {
  ami           = "ami-123456"
  instance_type = "t2.micro"
}

This tells Terraform to create an AWS EC2 instance.

Why Terraform is Used

  1. Create cloud infrastructure automatically
  2. Manage servers, networks, databases, storage, and more
  3. Avoid manual work in cloud consoles
  4. Reuse infrastructure code
  5. Track infrastructure changes
  6. Create the same setup in dev, test, and production environments

Important Terraform Terms

1. Provider

A provider tells Terraform which platform to work with.

provider "aws" {
  region = "us-east-1"
}

Common providers include:

  • AWS
  • Azure
  • GCP
  • Kubernetes
  • GitHub
  • Datadog
Provider is like a connection between Terraform and the cloud platform.

2. Resource

A resource is something Terraform creates or manages.

  • EC2 instance
  • S3 bucket
  • VPC
  • Subnet
  • Security group
  • Database
  • Kubernetes cluster
resource "aws_s3_bucket" "my_bucket" {
  bucket = "my-demo-bucket"
}

Here:

  • aws_s3_bucket = type of resource
  • my_bucket = local name in Terraform
  • bucket = actual bucket name

3. Terraform File

Terraform files usually end with .tf.

Common files:

  • main.tf
  • variables.tf
  • outputs.tf
  • provider.tf
  • terraform.tfvars

4. State File

Terraform keeps a record of created infrastructure in a state file.

terraform.tfstate

Terraform uses this file to know:

  • What resources exist
  • What changed
  • What should be created
  • What should be deleted
The state file is very important. In real projects, it is usually stored remotely, such as in an S3 bucket or Terraform Cloud.

Basic Terraform Workflow

Step 1: Write Terraform Code

Example file: main.tf

provider "aws" {
  region = "us-east-1"
}

resource "aws_s3_bucket" "demo" {
  bucket = "my-demo-terraform-bucket-123"
}

Step 2: Initialize Terraform

terraform init

This downloads required provider plugins.

Step 3: Check the Plan

terraform plan

This shows what Terraform will create, update, or delete.

Step 4: Apply Changes

terraform apply

This creates the infrastructure. Terraform will ask for confirmation. Type yes.

Step 5: Destroy Infrastructure

terraform destroy

This deletes the resources created by Terraform.

Main Terraform Commands

terraform init

Initializes project and downloads providers.

terraform validate

Checks whether the Terraform code is correct.

terraform fmt

Formats Terraform code properly.

terraform plan

Shows what Terraform will do.

terraform apply

Creates or updates infrastructure.

terraform destroy

Deletes infrastructure.

terraform show

Shows current state details.

terraform state list

Lists resources tracked by Terraform.

Variables in Terraform

Variables are used to avoid hardcoding values.

Example: variables.tf

variable "region" {
  default = "us-east-1"
}

variable "instance_type" {
  default = "t2.micro"
}

Use Variables in main.tf

provider "aws" {
  region = var.region
}

resource "aws_instance" "web" {
  ami           = "ami-123456"
  instance_type = var.instance_type
}

Output in Terraform

Outputs display useful information after Terraform creates resources.

output "instance_id" {
  value = aws_instance.web.id
}

After terraform apply, it may show:

instance_id = i-1234567890abcdef

Terraform Block Structure

Basic Terraform syntax looks like this:

block_type "label1" "label2" {
  argument = value
}

Example:

resource "aws_instance" "web" {
  ami           = "ami-123456"
  instance_type = "t2.micro"
}
  • resource = block type
  • aws_instance = resource type
  • web = local name
  • ami = argument

Terraform vs Manual Cloud Setup

Manual Setup

  • Login to AWS
  • Go to EC2
  • Click launch instance
  • Choose AMI
  • Choose instance type
  • Configure network
  • Create instance

Terraform Setup

resource "aws_instance" "web" {
  ami           = "ami-123456"
  instance_type = "t2.micro"
}

Then run:

terraform apply

Terraform creates it automatically.

Simple Example: Create S3 Bucket

provider "aws" {
  region = "us-east-1"
}

resource "aws_s3_bucket" "my_bucket" {
  bucket = "navya-demo-bucket-12345"
}

Commands:

terraform init
terraform plan
terraform apply

To delete:

terraform destroy

Simple Explanation

Terraform is like a blueprint for infrastructure.

You write what infrastructure you want:

  • I want one server
  • I want one database
  • I want one network
  • I want one storage bucket

Terraform reads that code and creates everything automatically in the cloud.

Terraform helps DevOps engineers manage infrastructure easily, repeatedly, and safely.
